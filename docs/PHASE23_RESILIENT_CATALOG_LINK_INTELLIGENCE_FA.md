# فاز ۲۳: کاتالوگ مقاوم و تحلیل هوشمند لینک

## هدف تجاری

3DPrintHub فروشنده فایل دیجیتال نیست؛ هدف اصلی دریافت سفارش و چاپ قطعه است. بنابراین نبود لینک مستقیم STL، 3MF یا STEP نباید باعث حذف کامل یک مدل از کاتالوگ شود.

## تغییر معماری کاتالوگ

هر مدل خارجی یکی از این وضعیت‌ها را دارد:

1. **مرجع قابل نمایش:** نام، تصویر، مشخصات قابل استخراج، طراح، نام منبع و صفحه اصلی مدل عمومی است.
2. **قابل بررسی برای چاپ:** علاوه بر اطلاعات مرجع، یک نشانه معتبر از فایل یا فرمت سه‌بعدی وجود دارد و مجوز تجاری نیز تأیید شده است.
3. **مخفی:** منبع یا سیاست نمایش مرجع آن غیرفعال شده است.

لینک مستقیم فایل و داده‌های خصوصی دانلود فقط در ادمین نگهداری می‌شوند.

## رفع علت خالی‌بودن کاتالوگ

نسخه قبلی برای نمایش عمومی هم‌زمان این موارد را لازم داشت:

- تأیید دستی انتشار
- مجوز تجاری صریح
- وضعیت مجوز allowed
- تصویر محلی ذخیره‌شده
- در بعضی Viewها وجود Preview Image دوباره بررسی می‌شد

فاز ۲۳ این شروط را از «نمایش مرجع» جدا کرده است. تأیید مجوز همچنان برای فروش/چاپ مستقیم معتبر است، اما برای نمایش نام، عکس و لینک منبع اجباری نیست.

Migration فاز ۲۳ همچنین عنوان رکوردهای قدیمیِ بدون نام را از آخرین بخش URL، شناسه خارجی یا نام منبع بازسازی می‌کند تا داده‌های قبلی نیز از کاتالوگ حذف نشوند.

## رفتار Sync مقاوم

اگر Adapter صفحه جزئیات را کامل بخواند، تمام اطلاعات قابل‌استخراج ذخیره می‌شوند. اگر صفحه جزئیات مسدود یا خراب باشد، Candidate کشف‌شده با عنوان، تصویر، خلاصه، آمار و لینک منبع به‌صورت مرجع ذخیره می‌شود. شکست دانلود تصویر نیز کل آیتم را حذف نمی‌کند.

## نمایش خودکار در سایت

- صفحه کاتالوگ همه مراجع فعال را نمایش می‌دهد.
- صفحه اول دیگر به ساخت دستی `CatalogAssetPublication` وابسته نیست.
- تصویر محلی اولویت دارد؛ سپس تصویر Remote و سپس Placeholder استفاده می‌شود.
- هر منبع دارای کلید `public_reference_enabled` است تا مدیر بتواند نمایش مرجع آن را متوقف کند.

## درخواست بروزرسانی مشتری

در صفحه جزئیات هر مدل، مشتری می‌تواند بروزرسانی همان لینک را درخواست کند. درخواست وارد صف دیتابیس می‌شود و توسط Cron یا فرمان زیر پردازش می‌گردد:

```powershell
python manage.py process_catalog_refresh_requests --limit 5
```

همچنین فرمان اتوماسیون فعلی `run_phase10_automation` این صف را پردازش می‌کند.

## Link Intelligence

مسیر عمومی:

```text
/store/link-analyzer/
```

سیستم به‌صورت Best-Effort این اطلاعات را استخراج می‌کند:

- عنوان محصول یا فایل
- نام سایت منبع و URL نهایی
- تصویر اصلی و تصاویر دیگر
- توضیح، طراح، برچسب و دسته
- JSON-LD و JSONهای اولیه React/Next
- ابعاد، نازل، ارتفاع لایه، Infill و چاپگر در صورت وجود
- وزن، زمان چاپ و متریال
- فرمت‌ها و لینک‌های احتمالی فایل؛ فقط برای ادمین

لینک مستقیم فایل نیز بدون دانلود حجیم ثبت می‌شود و مشتری مشخصات برآورد را تکمیل می‌کند.

## پنل مشتری برای تحلیل‌های لینک

مشتری واردشده از مسیر زیر به تاریخچه تحلیل‌های خودش دسترسی دارد:

```text
/store/account/link-analyses/
```

این صفحه تصویر، نام، دامنه منبع، وضعیت تحلیل، متریال، وزن، تعداد و برآورد قیمت را نشان می‌دهد و مشتری را به ادامه تحلیل یا سفارش مرتبط هدایت می‌کند. Query فقط رکوردهای متعلق به همان حساب را برمی‌گرداند.

## امنیت Link Grabber

- فقط HTTP و HTTPS
- فقط پورت 80 و 443
- مسدودسازی localhost، IP خصوصی، Link-local، Multicast، Reserved و Unspecified
- اعتبارسنجی دوباره Redirectها
- محدودیت حجم HTML و تصویر
- محدودیت تعداد تحلیل در ساعت
- عدم نمایش لینک‌های مستقیم فایل به مشتری
- نگهداری Payload امن‌شده، بدون HTML خام

## برآورد قیمت

قیمت اولیه از این اجزا ساخته می‌شود:

- نرخ فروش به‌روز هر گرم متریال
- وزن هر قطعه
- زمان چاپ و نرخ ساعتی دستگاه
- تعداد
- درصد اپراتوری
- بسته‌بندی
- تعدیل حداقل مبلغ سفارش
- بازه خطا بر اساس Confidence

این برآورد به `Order` و `Quote` فعلی تبدیل می‌شود. مشتری پیش‌فاکتور را تأیید می‌کند و سیستم رکورد `Payment` در انتظار پرداخت می‌سازد. اتصال درگاه بانکی واقعی همچنان به تنظیمات Merchant و Epic مالی نیاز دارد.

## فرمان سلامت

```powershell
python manage.py phase23_catalog_link_audit
```

خروجی شامل تعداد کل مدل‌ها، مراجع عمومی، مدل‌های بدون تصویر، سیاست‌های مخفی، درخواست‌های بروزرسانی و وضعیت تحلیل لینک‌ها است.

## Cron پیشنهادی

فرمان فعلی پروژه کافی است:

```powershell
python manage.py run_phase10_automation --limit 5
```

برای اجرای جداگانه صف بروزرسانی:

```powershell
python manage.py process_catalog_refresh_requests --limit 5
```

## Epicهای بعدی

### Epic 24 — Worker تحلیل لینک و صف غیرهم‌زمان
تحلیل لینک از Request وب جدا شود، Progress و Polling داشته باشد و Retry با Backoff اجرا شود.

ذخیره امن فایل، تشخیص هندسه، ابعاد، حجم، تعداد قطعات و اجرای Slicer برای وزن و زمان واقعی.

### Epic 26 — موتور پیشنهاد متریال
انتخاب متریال بر اساس دما، سایش، مواد شیمیایی، انعطاف و کاربرد قطعه.

### Epic 27 — پرداخت و تسویه
اتصال درگاه، Callback امضاشده، Idempotency، فاکتور نسخه‌دار و تطبیق پرداخت.

### Epic 28 — عملیات تولید
Kanban، صف دستگاه، پروفایل چاپ، کنترل کیفیت، ضایعات و تحویل.
