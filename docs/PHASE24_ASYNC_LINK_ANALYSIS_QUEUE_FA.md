# فاز ۲۴: صف غیرهم‌زمان تحلیل لینک

## علت خطای تست فاز ۲۳

تست `test_analyze_link_extracts_best_effort_and_estimates` تابع دریافت HTTP را Mock کرده بود، اما اعتبارسنجی DNS و SSRF را Mock نکرده بود. دامنه رزروشده `public.example.com` قبل از اجرای Mock رد می‌شد و تحلیل با وضعیت `failed` ذخیره می‌شد.

اصلاح فقط در تست انجام شده است. اعتبارسنجی DNS، جلوگیری از IP خصوصی، Redirect امن و محدودیت پورت در کد واقعی حفظ شده‌اند.

## معماری فاز ۲۴

هر تحلیل لینک اکنون یک `CustomerLinkAnalysisJob` دارد. اجرای هر Job در `CustomerLinkAnalysisAttempt` ثبت می‌شود.

وضعیت‌های Job:

- `queued`: در صف
- `running`: در حال اجرا
- `retry`: انتظار برای تلاش مجدد
- `completed`: تکمیل شده
- `failed`: ناموفق قطعی یا پایان تلاش‌ها
- `cancelled`: لغوشده

## Retry و Backoff

خطاهای شبکه، Timeout و کدهای HTTP موقت مانند 429، 500، 502، 503 و 504 با فاصله‌های زیر تکرار می‌شوند:

- ۳۰ ثانیه
- ۱۲۰ ثانیه
- ۶۰۰ ثانیه
- ۱۸۰۰ ثانیه

خطاهای امنیتی، لینک نامعتبر و محتوای غیرقابل پشتیبانی Retry نمی‌شوند.

## Worker

در توسعه ویندوز:

```powershell
& ".\RUN_PHASE24_WORKER.ps1"
```

یا مستقیم:

```powershell
python manage.py process_link_analysis_queue --watch --limit 3 --sleep 3
```

برای Cron، فرمان موجود `run_phase10_automation` صف تحلیل لینک را نیز پردازش می‌کند:

```powershell
python manage.py run_phase10_automation --limit 5
```

## رابط مشتری

ثبت لینک دیگر منتظر دریافت سایت خارجی نمی‌ماند. مشتری بلافاصله به صفحه وضعیت می‌رود و موارد زیر را زنده می‌بیند:

- درصد پیشرفت
- مرحله فعلی
- شماره تلاش
- انتظار Retry
- نتیجه نهایی

API وضعیت فقط برای مالک تحلیل یا کارمند مجاز قابل دسترسی است.

## بازیابی Worker متوقف‌شده

اگر Worker هنگام پردازش قطع شود، Job پس از ۱۵ دقیقه به حالت Retry برمی‌گردد و Worker دیگری می‌تواند آن را دریافت کند. Attempt نیمه‌کاره نیز با وضعیت خطای موقت بسته می‌شود تا گزارش مدیریتی رکورد «در حال اجرا»ی دائمی نداشته باشد.

تحلیل مجدد اجباری، شمارنده چرخه Retry را از صفر آغاز می‌کند اما شماره Attemptها به‌صورت افزایشی ادامه پیدا می‌کند؛ بنابراین تاریخچه قبلی حفظ می‌شود و Unique Constraint تکراری ایجاد نمی‌شود.
