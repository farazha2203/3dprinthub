# فاز ۲۹ — قیمت‌گذاری معتبر، صف اپراتور، حاکمیت منابع و سئوی کاتالوگ

## مسئله‌ای که این فاز حل می‌کند

سیستم قبلی ممکن بود عددهای عمومی صفحه مانند تعداد دانلود، تعداد لایک یا عدد موجود در JSON را به اشتباه وزن و زمان چاپ تلقی کند. نتیجه می‌توانست قیمت غیرواقعی برای محصولی باشد که سایت منبع هیچ وزن یا زمان چاپی اعلام نکرده است.

در فاز ۲۹ فقط این منابع برای قیمت خودکار معتبرند:

- مقدار صریح با برچسب وزن فیلامنت/قطعه و زمان چاپ؛
- پروفایل چاپ معتبر منبع یا اسلایسر؛
- مقدار تأییدشده اپراتور.

عددهای بدون برچسب، duration عمومی، تعداد دانلود، لایک، بازدید و تاریخ هرگز مبنای قیمت نیستند. اگر وزن، زمان یا متریال معتبر ناقص باشد، قیمت صفر می‌ماند و پرونده وارد صف استعلام اپراتور می‌شود.

## قانون زمان قابل محاسبه

دو تنظیم در «تنظیمات قیمت‌گذاری فروشگاه» اضافه شده است:

- حداقل زمان قابل محاسبه؛ پیش‌فرض ۶۰ دقیقه؛
- پله گردکردن؛ پیش‌فرض ۶۰ دقیقه.

با تنظیم پیش‌فرض:

- ۸ دقیقه = ۶۰ دقیقه قابل محاسبه؛
- ۶۰ دقیقه = ۶۰ دقیقه؛
- ۶۱ دقیقه = ۱۲۰ دقیقه؛
- ۹۰ دقیقه = ۱۲۰ دقیقه.

زمان واقعی در پرونده حفظ می‌شود و زمان قابل محاسبه جداگانه نمایش داده می‌شود.

## صف قیمت‌گذاری اپراتوری

تمام مدل‌های کاتالوگ یک رکورد در «صف قیمت‌گذاری اپراتوری مدل‌ها» دارند. اپراتور می‌تواند موارد زیر را وارد کند:

- متریال؛
- وزن واقعی هر قطعه؛
- زمان واقعی چاپ؛
- قیمت دستی اختیاری؛
- یادداشت و مشخصات فنی.

پس از تأیید:

- وزن و زمان روی مدل و تحلیل‌های مرتبط قفل می‌شوند؛
- قیمت با نرخ روز متریال محاسبه می‌شود؛
- دکمه محاسبه مجدد وزن/زمان از مشتری حذف می‌شود؛
- مشتری فقط تعداد را انتخاب می‌کند و پیش‌فاکتور می‌سازد؛
- Schema محصول فقط در این حالت Offer معتبر تولید می‌کند.

## استعلام لینک مشتری

برای لینک مشتری که اطلاعات کافی ندارد:

1. تحلیل بدون قیمت حدسی ذخیره می‌شود؛
2. بررسی دستی با اولویت بالا ساخته می‌شود؛
3. پیام اپراتور شامل عنوان، لینک اصلی و لینک مستقیم صفحه ثبت قیمت است؛
4. اپراتور وزن، زمان، متریال و مشخصات را ثبت می‌کند؛
5. قیمت قطعی به مشتری اعلان می‌شود؛
6. مشتری سفارش و بیعانه را از پیش‌فاکتور ادامه می‌دهد.

## اعلان اپراتور

کانال‌های قابل استفاده:

- Telegram Bot API؛
- WhatsApp Cloud API؛
- ایمیل SMTP به‌عنوان مسیر جایگزین.

متغیرهای محیطی در `.env.production.example` آمده‌اند. برای پیام آغازشده از سمت کسب‌وکار در واتساپ، Template تأییدشده Meta تنظیم شود.

بررسی تنظیمات:

```bash
python manage.py phase29_test_operator_alert
```

ارسال تست واقعی:

```bash
python manage.py phase29_test_operator_alert --send
```

در هر اجرای اتوماسیون، اعلان‌های ارسال‌نشده دوباره بررسی می‌شوند:

```bash
python manage.py run_phase10_automation --limit 10
```

## حاکمیت منابع

برای هر منبع این موارد قابل تنظیم است:

- فعال یا غیرفعال؛
- نمایش عمومی؛
- اولویت؛
- سقف دریافت؛
- Adapter و روش استخراج.

اولویت پیش‌فرض:

1. MakerWorld / Bambu Lab؛
2. Printables؛
3. Thingiverse؛
4. GrabCAD؛
5. منابع سفارشی.

غیرفعال‌کردن منبع، مدل‌ها و محصولات وابسته فاقد فایل محلی را از نمایش عمومی خارج می‌کند. این موارد حفظ می‌شوند:

- فایل دانلودشده؛
- فایل آرشیوی؛
- فایل نگهداری‌شده برای سفارش؛
- محصول دارای فایل سه‌بعدی محلی؛
- موردی که اپراتور صریحاً «حفظ در صورت قطع منبع» را فعال کرده است.

صرف ساخته‌شدن Product به‌تنهایی به معنی داشتن فایل نیست و باعث حفظ اشتباه محصول نمی‌شود.

## سئو

در این فاز افزونه قدیمی یا ناسازگار صرفاً برای زیادکردن تعداد افزونه نصب نشده است. قابلیت‌های فنی زیر مستقیماً در پروژه فعال است:

- Sitemap استاندارد Django برای صفحات کاتالوگ؛
- Image Sitemap کاتالوگ؛
- Canonical مستقل هر محصول؛
- Open Graph و تصویر اشتراک‌گذاری؛
- Product/CreativeWork JSON-LD؛
- Offer فقط برای قیمت تأییدشده؛
- noindex برای صفحات خصوصی تحلیل مشتری؛
- اولویت بیشتر Sitemap برای مدل‌های قیمت‌گذاری‌شده؛
- حذف مدل‌های منبع غیرفعال از صفحات عمومی و Sitemap؛
- لینک منبع اصلی با attribution؛
- تصویر و متن جایگزین قابل ایندکس.

افزونه‌هایی که با Django 6 سازگاری روشن ندارند یا با سیستم سئوی فعلی تداخل ایجاد می‌کنند نصب نشده‌اند. بعد از استقرار باید Google Search Console و Bing Webmaster Tools متصل شوند.
